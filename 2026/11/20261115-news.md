## 三条要点

1. **评测系统也需要防护。** Ragas 将多模态评测的安全修复纳入 0.4.4 正式版，browser-use 默认增加一次模型评判；前者保护数据边界，后者辅助验收，两者不能互相替代。
2. **长期 Agent 的核心问题是能否验证、纠正和删除。** AgentRun 把工作流学习与回放门槛连接，AgentOS 强化共享记忆的保留与删除；这些是工程机制，不是通用 RSI 已实现的证据。
3. **推理成本不能只看芯片峰值。** ONNX Runtime 的 CUDA 插件推进 CPU/GPU 混合 MoE，20VC 访谈则把内存、电力和机房容量放进同一个讨论框架。软件功能与厂商预测都需回到具体负载验证。

## 独立开源项目与工具链更新

以下发布时间均已按 GitHub API 的 published_at 核验，落在 **UTC 2026-11-14**；许可证以对应版本文本为准。正式版、预发布版与“原有功能首次出现”分别说明。

### 1. Ragas v0.4.4｜多模态评测安全修复进入正式版

- **时间 / 许可**：03:06:20 UTC（北京时间 11:06:20）；Apache-2.0，正式版。[Release](https://github.com/vibrantlabsai/ragas/releases/tag/v0.4.4) · [版本许可证](https://github.com/vibrantlabsai/ragas/blob/v0.4.4/LICENSE)
- **变化**：多模态指标读取图片时，检查实际连接的地址和每次重定向，限制内部地址访问；本地图片默认不加载，需显式限定允许目录。这针对 CVE-2026-6587 所述的 SSRF 与本地图片外传风险。
- **去重**：安全修复已在前一天的 rc1 中提供，今天是进入正式版；相较 rc1，新增 Bedrock 推理模型参数映射及弃用导入提示修复。[rc1 至正式版差异](https://github.com/vibrantlabsai/ragas/compare/v0.4.4rc1...v0.4.4)
- **用途 / 风险**：使用不可信数据集做 RAG 或多模态评测的团队应优先审查升级。图片加载策略和 Claude 采样默认变化可能改变评分，需查日志并重跑基线；HTTP 代理下仍存在最终目标地址可见性限制，不能视为完整网络隔离。

### 2. browser-use 1.0.5｜浏览器任务默认增加模型评判

- **时间 / 许可**：08:24:22 UTC（北京时间 16:24:22）；MIT。[Release](https://github.com/browser-use/browser-use/releases/tag/1.0.5) · [版本许可证](https://github.com/browser-use/browser-use/blob/1.0.5/LICENSE)
- **变化**：每次 run 默认额外调用用户配置的模型，评判成功或失败、提示注入、验证码阻断及站点注意事项；可用 judge_context 指定标准，或用 judge=False 关闭。
- **用途 / 风险**：适合为浏览器自动化增加结果审查记录，但会多一次模型调用及相应开销。模型 judge 的“成功”不是确定性验证，更不能替代付款、发信、写入等动作的真实回执或必要的人类确认。

### 3. ONNX Runtime CUDA Plugin EP v0.4.0｜CPU/GPU 混合 MoE 与量化执行

- **时间 / 许可**：06:34:19 UTC（北京时间 14:34:19）；MIT。[Release](https://github.com/microsoft/onnxruntime/releases/tag/plugin-ep-cuda/v0.4.0) · [版本许可证](https://github.com/microsoft/onnxruntime/blob/plugin-ep-cuda/v0.4.0/LICENSE)
- **变化**：扩展 CPU/GPU 混合 MoE 专家卸载、GGUF/block-packed 权重执行、INT2/3/4 与 NVFP4 QMoE 内核，并覆盖长上下文和投机解码路径。
- **用途 / 风险**：适合显存无法容纳全部专家的本地或边缘推理。最低 core 版本不代表新功能完整兼容，本版匹配 core 1.32.0，MoE offload 等能力需要该版本；官方建议 core/plugin 同 revision，避免算子 schema 不一致导致错误或崩溃。近似 tail 路由默认关闭，启用前应验证准确率。

### 4. LangGraph 1.2.22｜修复跨线程子图的流式事件

- **时间 / 许可**：01:43:55 UTC（北京时间 09:43:55）；MIT。[Release](https://github.com/langchain-ai/langgraph/releases/tag/1.2.22) · [版本许可证](https://github.com/langchain-ai/langgraph/blob/1.2.22/LICENSE)
- **变化**：修复独立 thread 上的子图向开启 subgraphs 的流式调用方传递事件；优化普通消息转换、宽 state 的键匹配，以及 pending writes/status 和运行终止条件。
- **用途 / 风险**：适合多 Agent 子图编排和高频流式执行。属于正确性和运行开销修复，没有支持“吞吐提升若干倍”的公开证据；checkpoint 与 Postgres 的独立包需分别管理，不能假设升级主包就全部包含。

### 5. AgentRun v0.1.0-beta.38｜工作流学习加入回放与晋升门槛

- **时间 / 许可**：23:10:31 UTC（北京时间 11 月 15 日 07:10:31）；Apache-2.0，Beta 预发布。[Release](https://github.com/Parcha-ai/agentrun/releases/tag/v0.1.0-beta.38) · [版本许可证](https://github.com/Parcha-ai/agentrun/blob/v0.1.0-beta.38/LICENSE)
- **变化**：学习代理可把任务编译成 learned workflow，匹配时优先执行；步骤 guard 低于阈值可退回普通 Agent。新版本需在已评分运行上回放、重拟阈值，才优先提供服务；pi、Claude Code、Codex 和 OpenCode 的 MCP 调用统一经过工具门禁。
- **用途 / 风险**：适合探索重复任务的受控工作流优化。发布说明未提供跨任务泛化或持续能力提升实验，并明确“自信但答错”的工作流可能不被成本规则捕获。升级涉及存储结构，回退需要备份；不能因 SQLite schema 号未变就假设可以直接降级。

### 6. AgentOS v0.18.0｜共享记忆要求保留策略，并防止删除被恢复覆盖

- **时间 / 许可**：10:34:21 UTC（北京时间 18:34:21）；Apache-2.0。[Release](https://github.com/framerslab/agentos/releases/tag/v0.18.0) · [版本许可证](https://github.com/framerslab/agentos/blob/v0.18.0/LICENSE)
- **变化**：多用户或多会话共享记忆库必须明确保留策略；增加用户记忆导出、纠正和 forgetUser。删除标记保留在备份恢复不会覆盖的位置，并在打开存储时重新应用，降低旧备份恢复已删记忆的风险。
- **用途 / 风险**：适合长期个人助理与多人共享 Agent 的记忆治理。这是破坏性升级；删除接口会报告未能触达的存储，不能概括为所有外部副本必然彻底清除，也不等于模型能力得到学习性提升。

## 热点与方向辨析

### AI Native / Harness：先设计验收，再让任务持续运行

本期几项更新可以连成一条工程链：LangChain 的目标与反馈设计、browser-use 的结果评判、AgentRun 的回放门槛、AgentOS 的记忆纠正与删除。编辑判断是，可靠 Agent 需要可审查的目标、行动回执、失败回退和数据生命周期，而不只是更多工具。模型自评、运行日志、真实外部状态和人工审核仍是不同层次的证据。

### RSI：有工作流学习机制，不等于已证实递归自我改进

AgentRun 的编译、回放与阈值调整值得跟踪，但它优化的是受约束的工作流；目标、评分样本、预算和工具权限仍由外部提供。本期没有核验到足以证明系统自主、持续提升通用能力的新增实验。安全补丁、记忆治理和推理内核优化也不作为 RSI 证据。
