- **时间口径：**OpenRouter 官方模型目录的 `created` 字段分别为 11 月 21 日 **02:19:45 UTC**（Inkling 2 Mini，北京时间 10:19:45）和 **00:49:48 UTC**（DaisyRose 27B，北京时间 08:49:48）。这是平台目录时间，不是全球首发或首笔调用时间。

### 3. Google Antigravity CLI 1.5.14：远程规划与权限变更

- **时间：**11 月 21 日 07:57:06 UTC（北京时间 15:57:06），GitHub 正式 Release。
- **变化：**远程 Agent 会话可进入规划模式，先给方案供人审阅。终端的多 Agent 看板新增目标、已完成数量及受阻状态。Auto 模式同时放宽工作区外普通文件的默认读权限；工作区外写入仍需审批，明确的询问／拒绝规则和组织策略仍适用。
- **安全提示：**版本还修复了 Windows 凭据暴露风险。Windows 团队优先安排版本验证与升级；同时复核环境级读权限，不以“无写权限”代替数据隔离。本条不推断事故范围或提供复现方法。
- **来源：**[官方 Release](https://github.com/google-antigravity/antigravity-cli/releases/tag/1.5.14)

## 三、值得关注的开源项目

### 4. Qwen Code 0.28.3：无界面后台工作流与重启恢复

- **时间：**GitHub 正式版于 11 月 21 日 01:45:48 UTC（北京时间 09:45:48）发布；npm CLI 包于 02:07:38 UTC 上传。
- **变化：**无界面运行可显式选择后台工作流，先拿到运行句柄，再接收完成通知，进程结束前等待运行中的后台工作流；不设置时仍以前台运行。Web Shell 侧栏可列出守护进程重启后中断的任务并选择继续，不是所有任务自动无损恢复。另一项聊天控制器改动只接通绑定层，主聊天界面尚未切换。
- **边界：**CLI 与 TypeScript SDK 分别发版。本期确认 CLI 包；关联 SDK 工作流曾取消，不能从同一仓库的更新说明推断 SDK 包同步上线。ACP 注册表在窗口内把 Qwen Code 条目更新到 0.28.3，也不等于所有宿主同步更新。
- **来源：**[官方 Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.28.3) · [后台工作流](https://github.com/QwenLM/qwen-code/pull/17809) · [恢复侧栏](https://github.com/QwenLM/qwen-code/pull/17677) · [聊天绑定层](https://github.com/QwenLM/qwen-code/pull/17895) · [ACP 注册表变更](https://github.com/agentclientprotocol/registry/releases/tag/v2026.11.21-e29b5bf)

### 5. T3 Code 夜间版加入结构化线程结果

- **时间：**11 月 21 日 01:49:16 UTC（北京时间 09:49:16），版本 `v0.1.12-nightly.20261121.5024`，标记为预发布。
- **变化：**支持请求经过结构校验的线程结果，供下游流程决定下一步；还可浏览已关联环境的线程，在需要交互时再连接。变更说明也列出了环境关系图。
- **企业判断：**可试验让子任务交付可验证的结果，而非只交一段总结。结构正确不等于内容真实，仍应检查引用的提交、文件和测试产物；夜间版本不作为默认生产版本。
- **来源：**[官方夜间版本说明](https://github.com/pingdotgg/t3code/releases/tag/v0.1.12-nightly.20261121.5024)

### 6. llama.cpp 夜间版增加实时双工语音支持

- **时间：**b12619 于 11 月 21 日 23:45:36 UTC（北京时间 11 月 22 日 07:45:36）发布，标记为预发布。更早的 b12613 于 19:40:37 UTC 发布，同在窗口内。
- **变化：**b12619 的多模态运行组件加入 Kyutai Hibiki 实时全双工支持；b12613 另处理 AMD Windows 上 Vulkan Flash Attention 的驱动兼容问题。
- **企业判断：**本地实时语音可开始针对目标设备验证，但支持一个模型不等于所有设备都能低时延运行。长会话、打断重入、音频延迟与内存都应单独测；这不是 Hibiki 模型权重首发。

### 7. OpenAI Ruby SDK 1.0.0：正式版伴随破坏性变更

- **时间：**11 月 21 日 03:46:16 UTC（北京时间 11:46:16），GitHub 正式 Release。
- **变化：**要求 Ruby 3.3.0 或更新版本。SDK 移除旧 Assistants／Threads 客户端与相应类型，迁移指向 Responses／Conversations；Responses 的压缩结果类型等也有变化。
- **企业判断：**不要只改依赖版本。先查语言运行时、旧接口调用与流式事件处理，再用代表性请求验证会话状态和工具返回。这条报道的是 SDK 行为变化，不从中推断服务端接口的停用时点。
- **来源：**[官方 Release](https://github.com/openai/openai-ruby/releases/tag/v1.0.0) · [迁移指引](https://github.com/openai/openai-ruby/blob/v1.0.0/docs/MIGRATION_1.0.0.md)

## 五、AI Native / Harness / RSI：今日可落地的检查

- **AI Native：**把试点目标写成可验收的业务结果，先跑辅助流程，再根据实测决定是否扩大范围。
- **Harness：**把“已接收、运行中、受阻、待人工恢复、已验收”分开。重启后，不仅核对会话是否还在，还核对已完成工作是否会重复执行。
- **RSI：**更新工作流、模型和权限策略时分开改、分开测；用固定回归样本和独立可查产物判断改动是否更好。这里是发布和工程信号，不是系统能自主持续改进的证据。
