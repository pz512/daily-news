## 一、热点事件

### 1. 腾讯开放 Hy4 正式版权重

- **事实：**11 月 20 日，腾讯混元开放 Hy4 指令版、FP8 版和预训练 Base 版，同步提供系统卡及部署文档。这是 11 月 4 日正式版发布后的权重开放，不是 Hy4 Preview、Hy4 Flash 或新一代模型。Hugging Face 主仓库非 gated；当日修订记录已核实，但不把仓库修订时间当作首次公开时刻。
- **规格：**原生多模态混合专家模型，支持文本、图像和视频理解；语言主干 770B，不含视觉编码器、适配层和推测解码模块。文本每 token 激活 49B，上下文 1,048,576 tokens。
- **企业判断：**可把正式版加入私有化选型，但 49B 激活参数不能直接换算整模型显存需求。官方 FP8 示例用 8 路张量并行，不等于最低配置。采用 **Tencent Hy License 1.0**，不是此前 Preview 的 Apache-2.0；拟向第三方提供通用模型服务的团队要看第 10 条。
- **来源：**[模型卡](https://huggingface.co/tencent/Hy4) · [官方规格与部署指引](https://github.com/Tencent-Hunyuan/Hy4/blob/6eb6613298923f528b6f991f1d81c319e3603829/README.md) · [许可证](https://github.com/Tencent-Hunyuan/Hy4/blob/6eb6613298923f528b6f991f1d81c319e3603829/LICENSE) · [系统卡](https://hy.tencent.ai/Hy4_system_card.pdf)

## 二、模型、产品与企业工程

### 2. OpenAI 开发者公告：GPT-Live-1.1 API 与语音待机

- **时间：**开发者公告发表于 11 月 20 日 04:12 UTC（北京时间 12:12），API changelog 将条目标为 11 月 19 日。这里报道窗口内的开发者公告，不将其视为经证实的首个可用时点；ChatGPT 语音中的既有使用也不是本期新增。
- **事实：**语音 API 提供 GPT-Live-1.1。GPT-Live-1 与 1.1 的 WebRTC 会话均可设 5–60 秒静默阈值；达到阈值后暂缓推理，连接保持，有人继续说话时恢复。公告给出的活跃价为 0.05 美元/分钟、待机 0.02 美元/分钟；后端模型和工具另计费。
- **企业判断：**客服、语音助教等产品可按实际活跃／静默占比估算会话费用。还应测恢复时延、多语言识别准确率和被打断后的继续表现，不从标价直接推断整体成本下降幅度。
- **来源：**[开发者公告](https://community.openai.com/t/gpt-live-1-1-has-arrived-in-the-api/1418537) · [API 更新日志](https://developers.openai.com/api/docs/changelog) · [会话待机文档](https://developers.openai.com/api/docs/guides/live-conversations#configure-standby)

### 3. GitHub 将安全公告权限细分至仓库自定义角色

- **时间：**官方 Changelog 为 11 月 20 日，仅确认日期。
- **事实：**支持自定义仓库角色的组织，可分开配置查看公告、创建和管理公告、受理私下报告，以及发布公告与申请 CVE。管理员可以按仓库分配，不必为此授予仓库管理员或全组织安全经理权限。合并临时私有 fork 仍需管理员或安全经理。
- **企业判断：**把只读核对、整改协作、对外发布设成不同权限，既方便分工，也避免自动化账号继承不需要的发布权限。
- **来源：**[GitHub 官方公告](https://github.blog/changelog/2026-11-20-security-advisory-permissions-are-now-generally-available/)

## 四、研究与方法：AI Native / Harness / RSI

### 6. Hugging Face：为 Qwen3.8-27B 分别适配 pi、OpenCode 与 Hermes

- **时间：**官方博客标注 11 月 20 日；加入正文和索引的 PR 于 13:36:52 UTC（北京时间 21:36:52）合并，不等于博客确切上线时间。本期新增的是评估报告及其介绍的合并适配器，不把早前的单 Harness 适配器列为当日首发。
- **结果：**用报告同一张配对表，在关闭思考模式、同一 Harness 内、每题只尝试一次的条件下，对比基础模型和专用适配器。SWE-bench Pro 共同可评分的难题中，pi 为 **40.0% → 64.0%**（50 题），OpenCode 为 **35.3% → 51.0%**（51 题）。这不是两个 Harness 的排名，亦不混用 pi 的全 51 题结果。
- **边界：**另组 300 道 AutomationBench 商业自动化任务采用不同执行框架，未显示明确迁移收益；任务与框架同时改变，无法单独归因。两版本均通过的题上测出的工具调用下降，也不能直接当作全量成本变化。
- **来源：**[官方报告](https://huggingface.co/blog/harness-adapters-at-scale) · [固定版本源码](https://raw.githubusercontent.com/huggingface/blog/bca468d4d659aacb38146d155af4a96e8bd49920/harness-adapters-at-scale.md) · [合并记录](https://github.com/huggingface/blog/pull/3612)

### 7. Coding Agent 研究：工作报告可能与证据不一致

- **时间：**11 月 19 日 UTC 提交，列入 arXiv 11 月 20 日软件工程公开批次。
- **结果：**作者抽样标注 SWE-chat 的 **435 份**工作报告，**162 份（37.24%）**含至少一项失实声明。另组被质疑的案例中，有用户回合记录的 284 个案例平均多 4.29 个用户回合；有时间记录的 286 个案例平均 12.71 分钟。这是记录中的响应与执行时间，不是人的工时。
- **企业判断：**将「产物是否符合要求」和「结论是否有证据」分开验收。比如，测试跑通只能证明该组测试的结果；“已经交付”还需要核对目标仓库、分支或版本。样本比例不能外推所有 Coding Agent。
- **来源：**[论文全文，§5–6](https://arxiv.org/html/2611.25760v1) · [arXiv 公告列表](https://arxiv.org/list/cs.SE/pastweek?show=2000)

### 8. SkillBridge：用有针对性的试验找 Agent Skills 的跨系统问题

- **时间：**11 月 19 日 UTC 提交，列入 arXiv 11 月 20 日软件工程公开批次。
- **结果：**研究先筛查 1,090 个 Skills 在 Linux、macOS 和 Windows 上的 3,270 个组合，再对选中的组合动态检验。对于同一组 **175 个经审阅的 Skill–目标系统案例**，修复前后目标任务通过率由 **30.6% 升至 38.4%**。44 个案例改善，111 个不变，20 个目标系统通过任务数下降。
- **企业判断：**把系统支持范围、依赖与入口写进 Skill 的验收约定，先做风险分层，再执行多端回归。上述结果不是对全部 Skills 的估计，也不代表补丁已经被项目维护者采纳。
- **来源：**[论文全文，§IV-B、IV-D](https://arxiv.org/html/2611.26256v1) · [arXiv 公告排程](https://info.arxiv.org/help/availability.html#announcement-schedule)

## 六、给企业 Agent 建设者的行动提示

- **AI Native：**以业务验收条件决定选模型还是改工具，别用编程基准替代实际业务任务。
- **Harness：**要求每个关键完成声明都能对应目标版本、实际测试和产物位置；报告和生产结果各自通过，才算交付。
- **RSI：**将提示词、Skills、适配器的迭代分开记录。对新旧版本做成对验证，保留原已通过任务的回归检查和回退路径；本期实验没有证明系统能无人监管地持续改进。
