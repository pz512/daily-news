> **覆盖区间：北京时间 2026-11-15 08:00 至 2026-11-16 08:00**（UTC 2026-11-15 00:00 至 11 月 16 日 00:00）。
>
> **证据口径**：以官方文档、GitHub Release、原始报道和会议议程为主，区分模型首发、API 开放、软件接入与媒体转载。只核到日期的条目明确标注，不补造发布分钟。厂商规格不等于独立性能验证；周末新增信息有限，不以旧闻凑数。

## 三条要点

1. **国内模型能力继续向开发者开放。** openPangu-2.1-Pro 上线华为云 MaaS，Seedance 2.5 flash 开放 API。两条都是可用性进展，不是模型当天首次出现，也不能据名称推断新权重已经开源。
2. **Coding Agent 开始把“任务相关”与“明确获准”分开。** Qwen Code 改进 AUTO 授权判断，gptme 增加工具执行前的拒绝接口；有审批机制仍不等于自动获得正确权限策略。
3. **RAG 升级首先是数据一致性问题。** LightRAG 候选版对 embedding 空间错配改为拒绝启动，PageIndex SDK 增加云端检索与抽取接口。升级前要确认数据迁移、服务依赖和内容流向，而非只看检索效果。

## 独立开源项目与工具链更新

以下均按 GitHub API 的 published_at 核验为 **UTC 2026-11-15** 的发布，并核对版本许可证。软件新增模型支持不等于模型本体当天首发，开源 SDK 也不代表其云服务能力可在本地运行。

### 1. Qwen Code v0.27.4｜托管工作区与明确授权判断

- **时间 / 许可**：07:04:40 UTC（北京时间 15:04:40）；Apache-2.0。[Release](https://github.com/QwenLM/qwen-code/releases/tag/v0.27.4) · [版本许可证](https://github.com/QwenLM/qwen-code/blob/v0.27.4/LICENSE)
- **变化**：Managed Agent 增加临时目录授权与 Web Terminal；飞书、企微提供仅发送 webhook 及长回复分段；AUTO 从判断操作是否“与任务相关”转向判断是否明确获准，并增强超时复核与 Full Access 警示。
- **用途 / 风险**：适合远程或托管 Coding Agent，以及企业消息交付。统一 Agent loop 与 event-bus 仍为实验、选择加入，默认保留旧路径；外发目标和目录权限必须精确设置，不能将 AUTO 改进概括为无需人工审查。

### 2. gptme v0.37.0｜执行前拦截与长任务恢复

- **时间 / 许可**：20:27:40 UTC（北京时间 11 月 16 日 04:27:40）；MIT。[Release](https://github.com/gptme/gptme/releases/tag/v0.37.0) · [版本许可证](https://github.com/gptme/gptme/blob/v0.37.0/LICENSE)
- **变化**：新增 TOOL_EXECUTE_PRE 拒绝接口，将敏感路径读取检查移到执行前；子 Agent 可保留 worktree 继续执行，并提供跨重启写入租约、终态持久化和显式清理路径。另有 MCP SSE、输出落盘限额和脱敏改进。
- **用途 / 风险**：适合多 Agent 编码与跨重启长任务。拒绝接口不是自动覆盖所有工具的完整策略引擎，shadow/off 模式不阻断；保留的工作区需要管理生命周期，不能把脏工作静默删除。[接口边界](https://github.com/gptme/gptme/pull/4918)

### 3. LightRAG v1.5.8rc1｜阻止 embedding 错配静默污染检索

- **时间 / 许可**：13:03:37 UTC（北京时间 21:03:37）；MIT，**候选版 RC**。虽然 GitHub 的 prerelease 字段为 false，正文明确要求按 RC 测试。[Release](https://github.com/HKUDS/LightRAG/releases/tag/v1.5.8rc1) · [版本许可证](https://github.com/HKUDS/LightRAG/blob/v1.5.8rc1/LICENSE)
- **变化**：记录各工作区向量目标的 embedding 空间基线，并把部署绑定到配置容器；模型、维度或配置后端不匹配时拒绝启动，避免返回错误邻居或空向量结果。增加离线重建、配置迁移和 chunk tracking 修复工具，强化图写入、删除、PDF 资源限制及 Ollama 兼容路由的 API-key 保护。
- **用途 / 风险**：面向持续运营的 RAG 知识库。要求 Python 3.11 以上；先备份、停掉所有旧 writer，不能旧新版混跑。即使数据全在数据库，WORKING_DIR 也必须持久化；首次建立基线时 embedding 服务需要可达。生产环境应先在数据副本验证，不因新增保护而跳过迁移测试。

### 4. PageIndex v0.7.0｜云端页级检索、结构化抽取进入 SDK

- **时间 / 许可**：18:54:51 UTC（北京时间 11 月 16 日 02:54:51）；MIT。[Release](https://github.com/VectifyAI/PageIndex/releases/tag/v0.7.0) · [版本许可证](https://github.com/VectifyAI/PageIndex/blob/v0.7.0/LICENSE)
- **变化**：新增 client.search/search_documents 的页级与文档检索、按 JSON Schema 或 Pydantic 模型进行结构化 extract 及任务管理、页面区域图像和 metadata 更新/过滤。
- **用途 / 风险**：适合文档问答、抽取及 Agent 的文档工具接入。本版这些新增能力大多是 **Cloud-only**，不能写成本地 RAG 已全部具备；开源的是客户端代码，云文档与自选模型供应商之间的数据流及费用仍需单独检查。发布页顶部的 Flash 与统一 SDK 是累计介绍，不当作今日全部新功能。

### 5. AgentOS v0.19.0｜减少宿主未明确选择的默认行为

- **时间 / 许可**：10:37:52 UTC（北京时间 18:37:52）；Apache-2.0。[Release](https://github.com/framerslab/agentos/releases/tag/v0.19.0) · [版本许可证](https://github.com/framerslab/agentos/blob/v0.19.0/LICENSE)
- **变化**：内置简洁 prompt preset 和日期工具改为显式启用；工厂保留 runtime 的持久化设置，不再未加区分地打开会话存储。检索文本作为独立说明加入，不改写用户原话，并修复结构化拒绝的传递。
- **用途 / 风险**：适合需要由宿主控制提示、工具与存储的 Agent runtime。这是破坏性更新，依赖旧默认值的应用要显式补齐配置并回归测试；不要与前一天 0.18 的记忆删除治理混为一次发布。

### 6. Lance v14.0.3｜多模态数据集的旧 blob 格式兼容修复

- **时间 / 许可**：06:27:21 UTC（北京时间 14:27:21）；Apache-2.0。[Release](https://github.com/lance-format/lance/releases/tag/v14.0.3) · [版本许可证](https://github.com/lance-format/lance/blob/v14.0.3/LICENSE)
- **变化**：修复文件格式提升后旧 blob 页的解码，以及 fragment/update 写入过程中 legacy blob 向 v2 的提升。
- **用途 / 风险**：影响含 blob 的多模态数据集读写与迁移，是正确性补丁，不是新的向量检索能力。迁移前保留原数据，并测试旧数据读取与更新后的再读取。

### 7. llama.cpp 夜构｜增加音频模型接入，不是新的稳定版

- **时间 / 许可**：b12424 为 20:08:40 UTC、b12425 为 20:22:29 UTC、b12426 为 21:05:49 UTC；均为 11 月 15 日的 **预发布夜构**，代码为 MIT。[版本许可证](https://github.com/ggml-org/llama.cpp/blob/b12426/LICENSE)
- **变化**：[b12424](https://github.com/ggml-org/llama.cpp/releases/tag/b12424) 加入 zonos3-mini TTS；[b12425](https://github.com/ggml-org/llama.cpp/releases/tag/b12425) 调整输出头读取，适配 Qwen3-ForcedAligner；[b12426](https://github.com/ggml-org/llama.cpp/releases/tag/b12426) 增加 higgs v3 STT 与 vibevoice-ASR。
- **用途 / 风险**：扩展本地语音合成、识别与对齐的接入面。仍需按模型和硬件验证，代码 MIT 不能替代权重许可证；这些是软件适配，不是三个模型今天首发，也不是继 11 月 13 日 1.0 后又发布了新的稳定大版本。

## 热点与方向辨析

### AI for Science｜AI4S’26 议程落在本窗口

[AI4S’26 官方议程](https://ai4s.github.io/)将研讨会安排在芝加哥时间 11 月 15 日 09:00–17:30 CST，即 UTC 15:00–23:30（北京时间 23:00 至次日 07:30）。议程包含两场特邀报告与 12 篇论文，关注科学工作流、规模化训练推理、可靠性、可复现性和能效。

本期核验的是官方安排，没有取得现场完成记录；不据此声称已出现新突破，也不把参会论文一律算作当天首次公开。

### AI Native / Harness：权限、上下文和数据版本应成为显式契约

Qwen Code 的授权判断、gptme 的执行前拒绝接口、AgentOS 的显式默认配置，以及 LightRAG 的 embedding 基线，分别处理行动权限、执行控制、上下文与数据一致性。编辑判断是，这些约束比单纯增加工具数量更接近长期可靠运行的需求；是否真正有效仍需用实际任务和故障场景检验。

### RSI：没有把普通软件迭代包装成能力自我提升

本期的工具门禁、记忆/提示配置、数据迁移与模型适配，都属于人为设计和维护的软件机制。未核验到本窗口内能够证明系统自主、持续提升通用能力的新实验，不将项目使用“学习”“自进化”或“AgentOS”等名称直接视为 RSI 证据。
