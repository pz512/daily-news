## 三条要点

1. **Qwen4-Max Preview 退场，旧 ID 仍可用，但实际模型和账单口径都变了。** 阿里云百炼 Token Plan 确认旧请求会转到正式版，预览折扣不再延续。[官方动态](https://docs.agent.bailian.aliyun.com/zh/token-plan/token-plan-product-updates)
2. **商汤给出模型与 Harness 共同迭代的具身实验。** 三轮后，两者一起改在该测试设置中比单改一项得分高；仍由研究者参与改工具、选轨迹和训练，不是机器人上线后自主升级。[团队原文](https://huggingface.co/blog/sensenova/roborsi)
3. **MCP 工具越来越容易串联，也更需要逐步审计。** FastMCP 新增实验性的跨服务编排；Claude Code 新增可在技能加载时拦截内联命令的钩子。分别涉及运行期工具调用和加载期命令，不能互相替代。[FastMCP 发布记录](https://github.com/PrefectHQ/fastmcp/releases/tag/v4.2.6) · [Claude Code 发布记录](https://github.com/anthropics/claude-code/releases/tag/v2.1.332)

## 热点事件

### 1. 【国内／产品变更】阿里云百炼确认 Qwen4-Max Preview 下线

**来源／日期：** 阿里云百炼 Token Plan，11 月 25 日 10:00（北京时间）为该渠道公告的下线时点。旧 ID `qwen4-max-preview` 仍能调用，但请求自动转到 `qwen4-max`，Credits 和用量统计按正式版计算，不再享受预览折扣。其他百炼模型更新页也确认自动转发，未自行测试各地区端点。**为什么值得关注：** HTTP 成功不等于调用行为未变。依赖预览版的团队应更新配置，用自己的工具调用和长文本用例复测，并拿实际账单核对成本。[Token Plan 产品动态](https://docs.agent.bailian.aliyun.com/zh/token-plan/token-plan-product-updates) · [百炼模型更新](https://help.aliyun.com/zh/model-studio/newly-released-models)

### 2. 【企业／计费公告】GitHub 将调整 Copilot 代码审查的默认付费方

**来源／日期：** GitHub Changelog，11 月 25 日（页面日期）。从 12 月 30 日起，未显式选择付费方的 Copilot Business／Enterprise 组织，已有许可证成员的代码审查将默认计入仓库所属组织。已明确选择 Member 或 Organization 的设置不变；未启用 AI Credits 付费用量或不满足计费条件的账户有例外；无许可证成员的独立设置也不变。**为什么值得关注：** 若团队要沿用成员额度，应在切换前检查策略是否明确选了 Member；这不是今天就开始收费。[GitHub 官方公告](https://github.blog/changelog/2026-11-25-copilot-code-review-billing-will-default-to-the-organization/)

## 研究与应用

### 3. 【国内／研究实践】SenseNova RoboRSI：怎么区分模型进步和工具进步

**来源／日期：** 商汤 SenseNova，11 月 25 日的技术文章。团队在 RoboDojo 的指定种子和布局下，从同一个模型出发做了三轮对照：只改 Harness 为 24.8、只更新模型为 32.2、两者共同迭代为 34.7，预览基线为 10.0。这些是任务进度分，不是成功率。固定最终 27B 决策权重、适配两台真机接口后，团队报告摆放 6/10、叠块 9/10。**为什么值得关注：** 值得借鉴的是同起点做对照，并保留执行轨迹供下一轮定位失败。工具修改与训练仍有人主导，少量真机试次不能证明跨平台泛化。27B 权重按 Apache-2.0 提供；今天的新内容是实验披露，不把权重当成今日首发。[实验原文](https://huggingface.co/blog/sensenova/roborsi) · [27B 模型卡](https://huggingface.co/sensenova/SenseNova-RoboRSI-27B)

### 4. 【算力／工程复盘】Hugging Face 在单卡上用 Coding Agent 调优 Inkling 2 Mini

**来源／日期：** Hugging Face，11 月 25 日（页面日期）。在单张 RTX PRO 6000、特定负载与软件版本下，团队将 SGLang 无投机解码基线换成 vLLM nightly 加 DSpark，报告单用户解码由约 136 提到 190.6 token/s，8 用户合计约 570 提到 716 token/s。**为什么值得关注：** 文中保留了无收益尝试，并分开验收解码速度、长上下文和并发稳定性。它是有验证门槛的参数调优，不是模型自我训练；数字也不能外推到其他 GPU 或生产流量。[原始测试报告](https://huggingface.co/blog/inkling-2-mini-inference-hillclimb)

### 5. 【企业应用／实例】IBM 把印度多语言语音与知识检索拆成可替换模块

**来源／日期：** IBM Research，11 月 25 日（页面日期）。CUGA 语音示例将识别、知识检索、文本回答与语音合成拆开：中间用手册检索作答，前端给出来源页，可替换云端或自管语音组件。**为什么值得关注：** 做多语言知识助手时，可以先验收文本正确性和引用，再单独量测口音、延迟及语音数据流向。它是教程与演示，不是识别准确率或合规已达标的证明。CUGA Harness 为 Apache-2.0。[原文与教程入口](https://huggingface.co/blog/ibm-research/an-indic-voice-agent-with-cuga) · [CUGA 仓库](https://github.com/cuga-project/cuga-agent)

### 6. 【研究访谈／治理】Ai2 访谈 17 位科学家：科研 Agent 不只要答对

**来源／日期：** Ai2，11 月 25 日（页面日期）。访谈将验证、隐私、客观性、问责与透明度列为五个信任维度。团队建议评估 Agent 是否忽略反面证据、是否遵守研究方法，以及是否越过获准访问的数据范围。**为什么值得关注：** 可以把过程留痕和权限边界纳入验收，而不是只评最终结论。研究是美国 17 人的探索性访谈，不是代表性调查，也没测试具体系统。[Ai2 原文](https://huggingface.co/blog/allenai/where-scientists-draw-the-line-on-ai-agents)

## 值得关注的开源项目

### 7. 【开源／正式版】FastMCP 4.2.6：客户端串联多个 MCP 服务

**来源／日期：** PrefectHQ 正式版与 PyPI，11 月 25 日；PyPI 软件包于当日 10:55（北京时间）上传。实验性 `CodeModeClient` 可以在客户端发现和串联不同服务的工具，无需每个服务自己实现 CodeMode。服务端追踪新增传输与协议字段。**适用与风险：** 适合先在只读流程验证跨系统编排；外层调用记录不能替代每个底层动作的授权和审计。事件实验功能拆为独立包且 API 有变；直接使用 Authlib 的应用须显式声明依赖。许可证：Apache-2.0。[正式版](https://github.com/PrefectHQ/fastmcp/releases/tag/v4.2.6) · [PyPI 上传记录](https://pypi.org/pypi/fastmcp/4.2.6/json) · [许可证](https://github.com/PrefectHQ/fastmcp/blob/v4.2.6/LICENSE)

### 8. 【开源／正式版】Goose v1.61.0：MCP 配置导入与上下文压缩进入开发套件

**来源／日期：** Goose 官方 GitHub，11 月 25 日。新版可导入 MCP Registry 的 `server.json`，为 `goose-agent` 增加 MCP 扩展和上下文压缩操作，并对 ACP 传入的 MCP 配置请求头按机密处理。**适用与风险：** 适合正在统一工具目录、需要长任务续跑的团队。导入配置不等于批准服务器，任务压缩前后的授权范围也应独立验证。许可证：Apache-2.0。[版本说明](https://github.com/aaif-goose/goose/releases/tag/v1.61.0) · [许可证](https://github.com/aaif-goose/goose/blob/v1.61.0/LICENSE)

## 开发工具配套更新

### 9. 【CLI 版本】Claude Code 2.1.332 增加技能加载期的控制点

**来源／日期：** Anthropic 官方 GitHub 版本记录，11 月 25 日。新钩子 `PreSkillShellCommand` 可在技能或命令加载时阻止其内联 shell 命令；后续常规工具调用仍由 `PreToolUse` 等机制处理。**为什么值得关注：** 团队部署共享规则前先与终端版本对齐：2.1.331 及更旧版本碰到含新事件的配置，启动会出现提示。此项是此前 MCP Skills 测试版的 CLI 治理后续，不当成另一个新功能首发。[CLI 版本](https://github.com/anthropics/claude-code/releases/tag/v2.1.332) · [官方钩子文档](https://code.claude.com/docs/en/hooks#preskillshellcommand)
