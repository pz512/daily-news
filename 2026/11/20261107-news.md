## 三条要点

1. **端侧 Agent 的适配和分发有了更明确的要求。** 工信部公开智能体终端进网管理通知，产品团队需要核对支持机型、系统版本与分发清单。
2. **开源工具本期的重点是权限、恢复与运行状态。** RAGFlow 1.0.0、Codex CLI 和 LangGraph 配套版本分别改进知识库访问边界、多 Agent 操作及人工审批恢复；升级仍需核对迁移和服务端兼容。
3. **AI 应用继续进入可持续使用的界面与数据流程。** Meta Muse spaces、BigQuery pandas 接口和 harness 适配实验值得看，但它们只有日期级时间证据，产品宣称与社区实验也需分别判断。

### 3. Agent Harness｜社区尝试为模型与运行框架组合训练适配器

- **来源/日期**：Hugging Face 社区文章标注 2026-11-06，未披露时区和时分，属日期级参考。[Harness adapters 原文](https://huggingface.co/blog/harness-hub/harness-adapters)
- **摘要**：harness-hub 在 pi、opencode、hermes 中用可验证任务开展强化学习，针对所用模型与 harness 的组合训练独立 LoRA adapter。作者介绍的 safeagents 会在执行前检查工具调用，检测到奖励投机时阻断并记零分。
- **为什么关注**：这将“模型、工具与控制流程”作为整体适配，而不只调整提示词。作者报告的小规模测试显示，部分组合在保持或改善留出任务准确率时减少了工具调用。
- **边界**：这是社区实验报告，不是 Hugging Face 公司的官方结论，也不是同行评审或独立复现。训练仍在持续，不能推导为普遍提效或自主递归自我改进。原文内容和日期来自搜索索引，正文直接读取失败。

### 4. 数据工作流｜BigQuery AI functions 接入原生 pandas 对象

- **来源/日期**：Google Cloud 原文标注 2026-11-06，未披露时区和时分，属日期级参考。[官方介绍](https://cloud.google.com/blog/products/data-analytics/bigquery-ai-functions-in-pandas)

- **边界**：这不是纯本地计算，也不意味着免费运行或发布了新基础模型。成本、数据权限与质量仍需按实际服务配置核对。本文提及的 TimesFM 3.0 已有更早记录，不列为今日首发。本次依据官方搜索索引，正文直接读取失败。

### RAGFlow v1.0.0｜正式版收紧检索权限并修复解析和恢复问题

- **发布时间**：2026-11-06 12:31:31 UTC（北京时间 20:31:31）；**许可证**：Apache-2.0。
- [版本公告](https://github.com/infiniflow/ragflow/releases/tag/v1.0.0) · [官方升级说明](https://ragflow.io/docs/release_notes) · [版本许可证](https://github.com/infiniflow/ragflow/blob/v1.0.0/LICENSE)
- **更新与场景**：三轮 RC 后进入 GA，相对 rc3 主要是关键缺陷修复和模型/供应商适配。值得关注的改动包括 PDF 子块覆盖、跨页句子保留、harness 中断恢复，以及 SQL 检索强制加入授权知识库过滤、删除块操作的数据集范围和注入防护。适合企业文档解析与 Agentic RAG 团队评估。
- **升级风险**：官方说明 rc3 数据兼容，可直接升级；从 v0.27.2 启动 Docker 容器时会自动迁移，更早版本需按文档操作。未核实到 v0.27.3 的明确迁移路径，不自行类推。升级前应备份并在副本中检查解析结果、检索权限和 Agent 恢复。更早已有的 Knowledge Compilation 等能力不作为当天新功能。

### Codex CLI 0.167.0｜改进多 Agent 操作和长会话状态

- **版本标签**：rust-v0.167.0；**发布时间**：2026-11-06 01:40:00 UTC（北京时间 09:40）；**许可证**：Apache-2.0。
- [版本公告](https://github.com/openai/codex/releases/tag/rust-v0.167.0) · [版本许可证](https://github.com/openai/codex/blob/rust-v0.167.0/LICENSE)
- **更新与场景**：`codex agents --no-daemon` 可打开 Agent command center 并显示未读结果；终端会话选择器可切换已连接后端且保留草稿。更新也处理网络审批提示的关闭和并发请求展示，并让自动上下文压缩保留失败响应及缺少 token usage 的输出。
- **边界与风险**：这些主要是终端工作流和状态可靠性改进，不代表模型能力跃升。系统代理仍需在实验功能中选择启用，Vertex AI 配置需开启对应 setup wizard，不能说默认开放。本文采用正式版，不用同日缺少实质说明的 alpha 版凑数。

### LangGraph SDK 0.4.14 / CLI 0.4.42｜把严格恢复校验接到客户端

- **发布时间**：SDK 为 2026-11-06 03:03:34 UTC，CLI 为 03:04:13 UTC（北京时间分别为 11:03:34、11:04:13）；**许可证**：MIT。
- [SDK 公告](https://github.com/langchain-ai/langgraph/releases/tag/sdk%3D%3D0.4.14) · [CLI 公告](https://github.com/langchain-ai/langgraph/releases/tag/cli%3D%3D0.4.42) · [strict_resume 变更](https://github.com/langchain-ai/langgraph/pull/9599) · [版本许可证](https://github.com/langchain-ai/langgraph/blob/sdk%3D%3D0.4.14/LICENSE)
- **更新与场景**：Python SDK 在同步/异步 `runs.create`、`stream`、`wait` 中接入 `strict_resume`，增加 tools/lifecycle 流事件；CLI 新增部署指标命令并更新依赖以处理安全修复。适合存在多标签页、并行审批和失败恢复的 Agent。
- **兼容性边界**：支持该功能的服务端在开启严格模式后，可拒绝已经回答过或 ID 错误的 interrupt，并保留线程状态；旧服务端会忽略该字段，只有 thread runs 会发送它。因此只升级 SDK 不能保证严格校验生效，需核实服务端和错误处理。相关 PR 于 11 月 5 日合并，本期收录的是 11 月 6 日 SDK/CLI 发布，不重复计算昨日 core 1.2.20。
