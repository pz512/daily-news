## 三条要点

1. **AI 钱包分成“经确认付款”和“只读分析”两条路线。** ChatGPT Wallet 从逐笔授权支付切入，Google Wallet 与 Gemini 的新连接则聚焦只读财务分析。二者权限边界不同，不能混称自动理财或无人值守消费。
2. **llama.cpp 进入 1.0，值得关注的不只是版本号。** 本地推理加入 FP8 KV cache、MoE 专家缓存与服务端安全修复，同时移除旧 API。Transformers、TRL 也集中调整部署和训练接口，升级前需要迁移测试。
3. **国内 Agent 产品从交互走向完整应用后端。** DeepSeek 把搜索、文件与工具编排开放为应用 API，腾讯 Hy Realtime 扩展语音工具调用，openEuler 提供运行底座；这不是同一轮基础模型首发，也不代表所有能力已普遍开放。

### 1. OpenAI 发布 ChatGPT Wallet：每笔购买仍由人确认

- **时间 / 来源**：官方公告日期 2026-11-13；Reuters 同日 10:43 EST（15:43 UTC，北京时间 23:43）的报道佐证本窗口内发布。[官方公告](https://openai.com/index/introducing-chatgpt-wallet/) · [Reuters 转载](https://www.streetinsider.com/Reuters/OpenAI%2Blaunches%2BChatGPT%2BWallet%2C%2Bletting%2BAI%2Bagents%2Bpay%2Bfor%2Bpurchases/27341091.html)
- **发生了什么**：首批面向美国 18 岁以上 Pro 用户，经 dots 渐进推出，支持符合条件的美国发行卡。用户需查看商品、总额和所用卡，并完成安全确认；支付网络提供 token，官方称不会把真实卡信息交给 Agent 或商家。
- **为什么重要**：Agent 商业化的障碍不仅是能否找到商品，还包括明确授权、支付凭证隔离、商家风控及失败后的处理。
- **边界**：限额预授权属于未来方向，不是当前默认功能；商家仍可能拒绝交易，不能理解为 Agent 获得了自由支配资金的权限。

- **时间 / 来源**：北京时间 2026-11-13，一财 16:38、IT之家 16:41:34 报道。[腾讯官方原文](https://mp.weixin.qq.com/s/bFxAT04ohJs9hPcjjin3bg) · [一财](https://www.yicai.com/brief/103440080.html) · [IT之家](https://www.ithome.com/1/026/825.htm)
- **发生了什么**：腾讯发布 Hy Realtime，新增工具调用和唱歌能力，已用于元宝及客服场景。实时语音因此不只负责“说话”，也可成为调用业务工具的交互入口。
- **边界**：腾讯云 API 尚未开放，不能写成开发者已可普遍调用。官方微信全文访问受限，本条依据两家媒体对发布的交叉转述；质量和效果仍是发布方口径。

### 3. openEuler 发布面向 Agentic Infra 的操作系统

- **时间 / 来源**：11 月 13 日北京大会发布；IT之家北京时间 18:47、第一财经 21:52:24 报道，官方大会页确认 11 月 13–14 日议程。[大会官网](https://www.openeuler.org/zh/interaction/summit-list/summit2026/) · [IT之家](https://m.ithome.com/html/1026911.htm) · [一财](https://www.yicai.com/news/103440538.html)
- **发生了什么**：openEuler 将 Agent 沙箱、KV Cache、记忆与安全等能力下沉至基础设施层，强调从传统服务器系统转向智能体运行环境。
- **为什么重要**：把隔离、状态和资源管理做成公共底层，可以减少各应用重复搭建运行环境的工作。
- **边界**：本条是大会产品与方向发布，不代表所有组件已完成相同成熟度的正式交付；性能、商业落地与装机数据不作为独立验证结论。

### 4. DeepSeek 开放“全家桶应用 API”：服务端接管工具编排

- **时间 / 来源**：官方更新日志标注 2026-11-13；一财北京时间 22:22 的晚间发布报道佐证入窗。[官方更新日志](https://api-docs.deepseek.com/zh-cn/updates/) · [一财](https://www.yicai.com/brief/103440559.html)
- **发生了什么**：deepseek-flash 在 Messages、Responses、Chat Completions 接口整合搜索、文件输入、链接阅读和基础安全校验；工具调用及上下文拼接由服务端处理。Search、Fetch、OCR、ASR、TTS 也可独立调用，另提供演示聊天客户端。
- **为什么重要**：从提供推理扩展到提供应用后端，可减少客户端自行拼接检索、解析与模型上下文的工作。
- **边界**：不是新基础模型；搜索 API 在 10 月 17 日已经开放，本次是应用能力的整合。工具另有计费，Demo 不等于生产级 App；安全校验也不替代开发者自身的内容审核与合规责任。[构建指南](https://api-docs.deepseek.com/zh-cn/guides/build_a_chatbot/)

## 独立开源项目与工具链更新

以下均已核验 **UTC 2026-11-13** 的正式 Release 时间及对应版本许可证。这里的“新增模型支持”指软件接入，不代表模型本体在当天首发；同一项目当天的连续小版本合并处理。

### 1. llama.cpp v1.0.0｜本地推理进入 1.0，并清理旧 API

- **时间 / 许可**：10:20:19 UTC（北京时间 18:20:19）；MIT。[Release](https://github.com/ggml-org/llama.cpp/releases/tag/v1.0.0) · [版本许可证](https://github.com/ggml-org/llama.cpp/blob/v1.0.0/LICENSE)
- **变化**：加入 FP8 KV cache、可配置 CPU 占比的主存 MoE 专家缓存和外部分片载入；扩展文本、视觉及语音模型支持，并新增兼容 OpenAI 的语音合成接口。服务端修复 SSRF、CORS、DNS rebinding 等边界问题，客户端断连或超时会取消 MCP 工具调用。
- **用途 / 风险**：适合本地、多硬件推理及下游应用集成。删除 35 个已废弃函数和若干配置，NextN/speculative API 迁移到公共头文件；需回归绑定、模型输出和服务端权限。MIT 只覆盖项目代码，不自动覆盖加载的模型权重。

### 2. Transformers v5.23.0｜统一模型导出与跨后端部署接口

- **时间 / 许可**：14:10:57 UTC（北京时间 22:10:57）；Apache-2.0。[Release](https://github.com/huggingface/transformers/releases/tag/v5.23.0) · [版本许可证](https://github.com/huggingface/transformers/blob/v5.23.0/LICENSE)
- **变化**：以 ExportedModel 统一 Dynamo、ONNX Runtime、OpenVINO 和 ExecuTorch 的导出、Hub 保存与载入；新增 Inkling2、LFM3、Dots 3 Note Preview、JEV 等架构接入，并修复视觉、缓存和专家并行问题。
- **用途 / 风险**：适合多模型接入与跨运行时部署。export() 返回类型、输出路径配置、专家并行和音频依赖都有破坏性变更；JEV/decision pipeline 仍属实验。维护者给出的性能数字依赖具体硬件和任务，本期不外推。

### 3. TRL v1.18.0｜异步 GRPO 进入稳定训练接口

- **时间 / 许可**：15:37:01 UTC（北京时间 23:37:01）；Apache-2.0。[Release](https://github.com/huggingface/trl/releases/tag/v1.18.0) · [版本许可证](https://github.com/huggingface/trl/blob/v1.18.0/LICENSE)
- **变化**：AsyncGRPOTrainer 升为稳定顶层 trainer，支持 vLLM rollout 与训练更新并行，加入 NCCL/LoRA 权重同步、tree packing、多轮 Agent 训练及零优势样本过滤。
- **用途 / 风险**：面向 LLM 与 Agent 的强化学习后训练。旧 experimental 子模块移除，参数、配置和指标有迁移要求；OpenEnv/Harbor harness 仍实验。示例被维护者明确称为 sanity check，而非加速基准，也不是自主递归改进的证明。

### 4. OpenCode v2.3.0｜子 Agent 默认转为后台执行

- **时间 / 许可**：08:55:07 UTC（北京时间 16:55:07）；MIT。[Release](https://github.com/anomalyco/opencode/releases/tag/v2.3.0) · [版本许可证](https://github.com/anomalyco/opencode/blob/v2.3.0/LICENSE)
- **变化**：子 Agent 默认后台运行、立即返回 session ID，空闲时向父会话汇报；shell 可跨服务端交接保留，加入 mTLS 客户端证书及恢复/OAuth 修复。
- **用途 / 风险**：适合并行 Coding Agent 与长任务。调用返回不再等同于任务完成，必须正确收集结果、处理取消和失败；MCP events 与超时转后台仍需实验开关。

### 5. FastMCP v4.2.0｜把可校验的 Skills 纳入 MCP 分发

- **时间 / 许可**：17:07:01 UTC（北京时间 11 月 14 日 01:07:01）；Apache-2.0。[Release](https://github.com/PrefectHQ/fastmcp/releases/tag/v4.2.0) · [版本许可证](https://github.com/PrefectHQ/fastmcp/blob/v4.2.0/LICENSE)
- **变化**：Skill 成为与存储无关的对象，可经普通 resources 或实验性 Skills extension 提供；Client.read_skill 校验文件大小与摘要，并支持 mounts、proxy、ClientGroup 和认证中间件。
- **用途 / 风险**：适合向不同 Agent 客户端分发可验证技能包。要求 Python 3.11 以上，4.1 的旧 Skills API 计划在 4.3 删除；客户端支持不一致，内容完整性校验不等于技能代码安全审计。

### 6. Vercel AI SDK ai@7.0.173｜保护“已批准参数”不被重放时改写

- **时间 / 许可**：22:34:02 UTC（北京时间 11 月 14 日 06:34:02）；Apache-2.0。[Release](https://github.com/vercel/ai/releases/tag/ai%407.0.173) · [版本许可证](https://github.com/vercel/ai/blob/ai%407.0.173/LICENSE)

- **用途 / 风险**：面向持久 Agent 的审批一致性和超时控制。toolApproval 的优先级高于工具 needsApproval，升级后需回归批准、拒绝与重试分支，避免以为旧审批配置仍原样生效。

### 7. Codex CLI rust-v0.169.0｜多会话工作区与项目信任边界

- **时间 / 许可**：08:37:05 UTC（北京时间 16:37:05）；Apache-2.0。[Release](https://github.com/openai/codex/releases/tag/rust-v0.169.0) · [版本许可证](https://github.com/openai/codex/blob/rust-v0.169.0/LICENSE)

- **用途 / 风险**：更适合多任务编码与远程环境。修复未信任目录中 codex exec 错用项目配置/MCP 的问题；workspace-write 不是项目受信任的同义词。工作区与 Cloud 连接等功能仍需选择启用，不能写成默认开放。

### 8. Nod v0.7.6｜主动准备工作的开关、额度和命令记录

## 热点与方向辨析

### 欧盟领导人在都柏林讨论 AI 战略

- **时间 / 来源**：欧洲理事会确认 2026-11-13 会议；官方会后讲话为同日日期级证据，未自行补填时区。[会议议程](https://www.consilium.europa.eu/en/meetings/european-council/2026/11/13/) · [会后讲话](https://www.consilium.europa.eu/it/press/press-releases/2026/11/13/remarks-by-president-antonio-costa-at-the-press-conference-following-the-informal-meeting-of-heads-of-state-or-government-of-13-november-2026/)
- 讨论聚焦 AI 竞争力、主权、基础设施、能源、投资和治理；Arthur Mensch 与 Geoffrey Hinton 参加讨论。官方称将在 2027 年 2 月 5 日继续议题。
- **边界**：这是战略讨论，不是新法规已经通过，也不代表资金已经到位。

### AI Native 与 Harness：价值在可靠交接，不在“会调用工具”这个标签

OpenCode 的后台子 Agent、Nod 的主动检查和命令记录、FastMCP 的技能分发，以及 Vercel 的审批参数保护，指向同一个工程问题：长期任务如何保存状态、维持授权、交接工作并留下可核对结果。Wallet 则把这条链延伸到支付确认。以上是基于本期更新的编辑分析，不是统一基准测试结论。

### RSI：普通训练与工具迭代不等于递归自我改进

TRL 的异步 RL、可复用 Skills、记忆或后台执行，仍由人规定目标、数据、预算和验证流程。本期未核验到足以支持“系统自主、持续提升自身通用能力”的新证据，不把普通 Agent 工程升级包装成 RSI 突破。

### EvoX 六种 Harness 对比：有信息量，但不是 RSI 实证

- **时间 / 来源**：官方研究页结构化发布时间为 2026-11-13 06:48:12 UTC（北京时间 14:48:12）。[原始研究博客](https://evomap.ai/research/evox-six-harness-benchmark)
- 研究比较六个模型与六种 Harness，采用从五个基准抽取的 132 项任务；统计 691 个六方均有有效结果的“任务×模型”组合。重要设置是 memory、evolution、extensions 全部关闭，因此测试的是基础运行时，而非自我改进机制。
- **边界**：这是厂商自测与任务子样本，不是完整基准的独立复现，不能据此宣称全面领先或 RSI 已经有效。

本期没有为补足数量而收录缺少首发时间或原始内容的新论文、播客和访谈。聚合器在 11 月 13 日列出的 Singularity-Bench、Experience-Handoff RL、Evidence-Governed Adoption，其 arXiv 首版均在 11 月 12 日；InfraRSI 更早至 11 月 8 日。它们不属于本期严格窗口。媒体在当天重提的旧产品与旧政策也不作为首发新闻；“未纳入”不表示这些领域当天没有更新。
