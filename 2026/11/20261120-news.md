## 今日三条要点

1. **可等待的 Agent 任务开始有明确价格档位。** OpenAI 后台请求新增 2 小时、8 小时完成窗口公测，对符合条件的模型 token 分别优惠 30%、40%；不是整条业务流程的交付时限保证。
2. **国内 AI 云需求有新的财务信号。** 阿里公布季度业绩，AI Cloud and Compute Services 收入同比增长 53%；要区分业务板块收入、外部客户收入与纯 AI 产品收入。
3. **RSI 要分清“改指令”和“改权重”。** 两篇新公开预印本分别研究个人 Agent 更新验收与模型权重内化；企业近期更可落地的仍是受控更新、回归测试和失败回滚，而非无边界自我进化。

## 一、模型、产品与企业工程

### 1. OpenAI：后台模式新增可折扣的完成窗口

- **时间：**11 月 19 日 06:39 UTC，即北京时间 14:39，官方社区发布。
- **事实：**Responses API 后台模式的 2h / 8h 完成窗口进入公测。官方以 GPT-6.2 Astra、Sol 等适用模型说明用途；文档列明，相对 Standard 模型 token 费率分别降低 30% / 40%。窗口从初始请求被接受开始，目标只针对该次响应；折扣按每个符合条件的请求计算。
- **价值：**夜间文档检查、工单预处理等不要求即时回复的工作，可以把“何时完成”纳入成本策略。
- **边界：**不是全流程 SLA，也不是所有模型、工具费用一律打折。多轮续接需要遵守模型、项目、窗口及 continuation ID 等条件；部署前核对适用范围。
- **来源：**[官方公告](https://community.openai.com/t/reduce-costs-using-background-mode-with-completion-windows/1418130) · [后台模式文档](https://developers.openai.com/api/docs/guides/background)

### 2. 阿里季度业绩：AI 云与计算服务增长，但别混淆口径

- **时间：**官方业绩公告日期为 11 月 19 日，未以网页日期推断分钟级发布时间。
- **事实：**截至 2026 年 9 月季度，AI Cloud and Compute Services 收入为人民币 609.73 亿元，同比增长 53%；调整后 EBITA 为 88.38 亿元。该口径包含 Cloud Intelligence Group 和 T-Head，不等于纯 AI 产品收入。官方业务说明另列外部收入增长 64%、AI 相关产品收入连续 13 个季度三位数增长。
- **价值：**为企业 AI 基础设施需求提供了公司财务层面的观察点。
- **边界：**这是发行人披露，不直接证明客户侧 Agent 项目的 ROI，也不能将外部收入增速套用到整个板块。
- **来源：**[发行人 SEC 财报附件](https://www.sec.gov/Archives/edgar/data/1577552/000110465926130115/tm2630263d1_ex99-1.htm) · [阿里官方业务说明](https://home.alibabagroup.com/en-US/document-2060213191907999744)

### 3. GitHub：Azure DevOps 实时迁移正式可用

- **时间：**官方 Changelog 日期 11 月 19 日，仅核到日期。
- **事实：**Enterprise Live Migrations 支持从 Azure DevOps Services 迁至带数据驻留的 GitHub Enterprise Cloud。迁移期间可持续同步，最后短暂切换；覆盖 Git 历史、分支、标签、PR 及部分关联信息，分支策略可转成 GitHub rulesets。
- **价值：**准备统一 AI Coding 工作台的企业，可以把迁移停工风险与治理规则搬迁一起评估。
- **边界：**不是所有研发资产一键搬走。Azure Boards 工作项、Azure Pipelines 定义仍留在 Azure DevOps；需检查连接和重新绑定安排。
- **来源：**[GitHub 官方公告](https://github.blog/changelog/2026-11-19-enterprise-live-migrations-from-azure-devops-generally-available/)

### 4. GitHub：GHE.com 审计日志到 S3 支持 OIDC

- **时间：**官方 Changelog 日期 11 月 19 日，仅核到日期。
- **事实：**使用 OpenID Connect 将企业审计日志流式发送至 S3 的能力扩展到 GHE.com 数据驻留环境，避免在 GitHub 保存长期 AWS 凭据。
- **价值：**对自动化账号和 Coding Agent 较多的团队，日志归档与短期身份凭证可以一起设计。
- **边界：**这是既有功能的覆盖范围扩展，不是首次推出审计日志；仍需配置 IAM 信任、最小权限、保留周期和告警。
- **来源：**[GitHub 官方公告](https://github.blog/changelog/2026-11-19-s3-audit-log-streaming-with-openid-connect-expands-to-ghe-com/)

## 二、值得关注的开源项目

### 5. gptme 开发快照：工具执行前阻断与工作区一致性

- **版本与时间：**v0.37.1.dev20261119，11 月 19 日 19:59:40 UTC，即北京时间 11 月 20 日 03:59:40；GitHub 标记为预发布。
- **变化：**发布说明包含在工具执行前执行 anomaly_watchdog 的阻断模式、对结构化工具输入应用护栏，以及会话工作区、子 Agent 工作目录等一致性修复；超长工具输出可落盘，减轻上下文负担。
- **借鉴：**Harness 不应只在最终回复时判断风险，执行前的阻断和正确工作目录同样重要。
- **边界：**这是开发快照，不是稳定版承诺；不能由这些修复推断“已杜绝泄密”。建议用隔离测试任务验证后再升级。
- **来源：**[版本说明](https://github.com/gptme/gptme/releases/tag/v0.37.1.dev20261119)

### 6. llama.cpp：夜间构建继续补齐推理正确性与后端支持

## 三、研究与方法：AI Native / Harness / RSI

> 下列两篇论文均在 11 月 18 日提交，但进入 arXiv 的 **Thu, 19 Nov 2026** 公开公告批次。按 arXiv 正常公告排程，对应北京时间 11 月 19 日约 09:00，属于本期公开窗口。这里不把提交时间写成首发时间。
> 核验依据：[cs.SE 公告列表](https://arxiv.org/list/cs.SE/recent?show=500&skip=0) · [cs.CV 公告列表](https://arxiv.org/list/cs.CV/recent?show=500&skip=0) · [arXiv 公告排程](https://info.arxiv.org/help/availability.html#announcement-schedule)

### 7. Safe Personal RSI：先验收更新，不通过就保留旧版本

- **事实：**研究将 RSI 限定为可复用指令的更新，固定模型权重与运行时代码。流程对照新旧指令、重复失败案例、撤回部分修改帮助修复，并在安全与任务表现达标后才采纳。
- **证据：**作者给出 29 个邮件、日历、健康及市场场景案例，跨三个模型、两类刻意危险修改的实验中，拒绝了 21 次更新尝试中的 20 次。
- **价值：**适合借鉴为企业 Skills / Prompt 更新的发布门禁：测试、修复、重新验收，不通过则不发布。
- **边界：**预印本与有限基准，不代表生产安全证明；“拒绝率高”也不能单独等同于业务效能高。它不研究模型自主改权重。
- **来源：**[论文摘要与全文入口](https://arxiv.org/abs/2611.23651)

### 8. BaseRSI：尝试把外部 Harness 的增益写进模型权重

- **事实：**作者提出 Recursive Harness Internalization：先改善外部 Harness，再用无需传统训练的权重编辑，把它产生的内部激活差异写回模型。ReGap 提供逐层差异信号，ReKey 用回归方式选择和更新部分神经元。
- **价值：**这与“不断修改提示词”的 RSI 是不同技术路线，值得研发团队跟踪可重复性、编辑副作用和收益保持情况。
- **边界：**预印本中的方法与作者实验，不是已验证的通用自我进化系统；“training-free”不等于“不修改权重”。本期不将论文存在等同于已发布可商用权重或成熟产品。
- **来源：**[论文摘要与全文入口](https://arxiv.org/abs/2611.24578)

## 六、给企业 Agent 建设者的行动提示

以下是基于本期材料的编辑判断，不是来源中的效果承诺：

- **AI Native：**将任务分成即时、两小时、隔夜等交付档位；同时记录业务截止时间与实际完成时间，避免把低价模型响应当成完整交付保证。
- **Harness：**把工具执行前授权、最小权限凭证、正确工作区、持久化输出和审计日志纳入同一条验收链。
- **RSI：**近期优先建设“提案 → 固定回归集 → 安全检查 → 小范围上线 → 可回滚”的更新流程；研究性权重编辑与生产发布分开管理。
