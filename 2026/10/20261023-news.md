## 今天先看 3 件事

1. **开源语音模型进入企业可用区间**：IBM Granite Speech 5.0 发布 Apache 2.0 的 2B 与 470M 系列，覆盖多语种转写、翻译、关键词偏置和说话人归因，并支持 Transformers、vLLM、llama.cpp 和 Apple Silicon。
2. **RAG 正从“向量检索”走向多模态检索 + 解析 + 重排**：NVIDIA 发布 Nemotron 3.5 Embed、Rerank 和 Parse 开放权重组合，直接面向图表、表格和复杂 PDF 的 Agent 检索链路。

## 精选内容

### 1. 开源模型｜IBM Granite Speech 5.0

- 来源/日期：Hugging Face 上 IBM Granite 官方文章，页面标注 2026-10-21；模型卡在本窗口内更新
- 摘要：Granite Speech 5.0 新增 2B 模型，并更新 470M Turbo CTC 与 4.1 2B Plus。2B 支持英语、法语、德语、西班牙语、葡萄牙语和日语转写，并支持多语种到英语的翻译；可用最多 2,000 个关键词做领域偏置。470M 面向高吞吐和端侧转写，4.1 2B Plus 强化说话人归因、时间戳和长语音。
- 为什么值得关注：企业语音应用的关键不只是 WER，还包括术语、说话人、时间戳、端侧成本和许可证。该系列明确支持 Apache 2.0、Transformers、vLLM、llama.cpp 和 mlx-audio，适合做私有化语音助手、会议和工厂语音记录的基线。
- 证据边界：性能数字来自 IBM 自测和公开榜单；应按中文、噪声、远场和行业词表独立复测。
- 原始来源：[Granite Speech 5.0](https://huggingface.co/blog/ibm-granite/granite-speech-5)

### 2. 开源检索模型｜NVIDIA Nemotron 3.5 Embed、Rerank、Parse

- 来源/日期：Hugging Face 上 NVIDIA 官方文章，页面标注 2026-10-21；模型权重在近 1–2 天更新
- 摘要：NVIDIA 发布 Embed 8B/1B、Rerank 8B 和 631M Parse，覆盖文本与图像检索、候选重排、表格/图表/PDF 结构化解析。官方称 ParseBench 上 1B 以下模型排名第一，并提供 BF16、NVFP4 和 NIM 部署路径。
- 为什么值得关注：这是对企业 RAG 痛点的直接回应：扫描 PDF、跨页表格、图表和文档结构不能只靠纯文本 embedding。Parse 先恢复结构，Embed 找证据，Rerank 再决定进入上下文的内容，形成更完整的 Agent 检索链。
- 证据边界：榜单、吞吐和 token 成本是 NVIDIA 披露，尚未独立复测；许可证和商业使用条件应以各模型卡为准。
- 原始来源：[Nemotron Retriever 文章](https://huggingface.co/blog/nvidia/nemotron-retriever-world-class-agentic-retrieval) · [模型集合](https://huggingface.co/collections/nvidia/nemotron-retriever)

### 3. 开源机器人｜Microduck + Isaac Lab 3.0 仿真到真实部署

- 来源/日期：Hugging Face/NVIDIA 教程，页面标注 2026-10-21；本窗口内持续被 GTC Berlin 社区传播
- 摘要：教程展示如何在 Isaac Lab 3.0 中训练开源双足机器人 Microduck 的行走策略，使用 Newton 执行器建模和域随机化，导出 ONNX 后部署到真实机器人，并通过 Hugging Face Hub 和 Microduck Arena 分享、比较策略。
- 为什么值得关注：它把“机器人学习”拆成可复现链路：仿真环境、观测/动作接口、奖励、训练、评估、模型导出、硬件部署和公开排行榜。对制造业和具身智能研发，这种闭环比一次性演示更有参考价值。
- 证据边界：教程中的训练速度、仿真到真实效果与硬件可用性受 GPU、机器人配置和控制参数影响；不要把教程结果当作通用机器人能力。
- 原始来源：[教程](https://huggingface.co/blog/nvidia/microduck-isaac-lab-sim-to-real) · [Microduck 仓库](https://github.com/pollen-robotics/microduck) · [Isaac Lab](https://github.com/isaac-sim/IsaacLab)

### 4. 开源资产｜NVIDIA SimReady Central

- 来源/日期：Hugging Face 上 NVIDIA 官方文章，页面标注 2026-10-21
- 摘要：SimReady Central 提供面向机器人和 AI 工厂的可复用、仿真就绪 3D 资产库，目标是减少搭建数字孪生、训练环境和工业场景的重复工作。
- 为什么值得关注：具身 Agent 的瓶颈不只在模型，也在场景资产、物理属性、传感器和可复现实验。标准化资产库有助于把“AI 工厂”从概念演示推进到仿真、评测和部署。
- 证据边界：应逐项核对资产许可证、物理精度和与具体仿真器的兼容性；开放资产不等于可直接用于商业生产。
- 原始来源：[SimReady Central](https://huggingface.co/blog/nvidia/simready-central-assets-robotics-ai-factories)

### 5. Agent 工具链｜Claude Code v2.1.307 增加 safety_event

- 来源/日期：版本发布据 Anthropic Claude Code GitHub Releases 的二手核验，2026-10-21/22；官方发布页当前抓取存在滞后
- 摘要：公开发布记录显示，v2.1.307 增加 `/claude-api api-version`，并增加 `claude_code.safety_event` OpenTelemetry 事件，用于记录权限规则、自动模式、安全检查、Hook 或沙箱对工具调用的停止、拦截或回退。
- 为什么值得关注：Coding Agent 的 Harness 需要知道“工具调用做了什么”，也需要知道“为什么没有执行”。安全事件可观测性有助于审计、误拦截诊断、策略调优和长期运行。
- 证据边界：版本细节主要依据公开 release 记录与社区核验，使用前应在官方仓库确认对应 tag、变更日志和兼容性。
- 原始来源：[Claude Code Releases](https://github.com/anthropics/claude-code/releases) · [变更核验文章](https://dev.classmethod.jp/en/articles/20261022-cc-updates-v2-1-307/)

## 热点事件

### 热点一：开源 Agent 栈从“模型权重”扩展到运行时与环境

- 背景：模型权重只是 Agent 的一部分，长期任务还需要工具、环境、记忆、权限和验证器。
- 最新进展：Granite Speech、Nemotron Retriever、Microduck/Isaac Lab、Hermes 插件和 Claude Code safety_event 分别覆盖感知、检索、环境、动作和运行时治理。
- 可能影响：企业选型会从“哪个模型最好”转向“哪套开源组件能组成可审计闭环”。
- 事实/分析区分：各项目发布为事实；能否在生产中形成稳定闭环仍是分析，需自行集成验证。

### 热点二：机器人训练开始强调公开策略评测与硬件回放

- 背景：仿真指标无法自动证明真实机器人可用，sim-to-real 差异来自摩擦、延迟、机械间隙和传感器噪声。
- 最新进展：Microduck 教程给出域随机化、ONNX 导出、真实机器部署和 Arena 评测路径。
- 可能影响：机器人 Agent 的竞争将更多围绕可复现实验、策略共享、真实硬件回放和安全控制展开。
- 事实/分析区分：教程流程和仓库为事实；“能普遍降低机器人研发成本”尚无独立证据。

### 热点三：Agent 的安全性进入“可观测、可停止、可解释”阶段

- 背景：长时间运行 Agent 的风险不只在错误答案，还在工具调用、权限升级、沙箱拦截和子 Agent 扩散。
- 最新进展：Claude Code safety_event、NVIDIA OpenShell/Sentry 内容都把运行时决策和外部控制放到核心位置。
- 可能影响：企业 Harness 必须记录每次动作、阻断原因、权限上下文和恢复路径，不能只保存最终对话。
- 事实/分析区分：功能与架构是官方/项目披露；安全效果和合规价值需独立评估。

## AI Native、Harness 与 RSI 观察

- **AI Native**：本期更清晰的信号是“模型 + 环境 + 工具 + 运行时”一体化，而非单独调用大模型。
- **Harness**：检索模型、机器人仿真、插件目录和 safety_event 共同说明 Harness 需要证据、环境、权限、可观测性和可回放机制。
- **RSI**：本窗口没有发现可独立核验的“模型自主改写自身训练/代码并递归提升”证据。Microduck 的训练闭环是人工设计的 RL 环境，Claude Code safety_event 是治理能力，均不应写成完全自主 RSI。
